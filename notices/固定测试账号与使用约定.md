## 身份与数据保留

- “风中闻笛”为用户本人真实微信身份，不属于测试账号。保留微信绑定、资料、陪玩档案及业务记录；不得使用该账号做模拟测试。
- 两个测试陪玩当前均属于王者荣耀。测试指定或更换陪玩，请使用王者荣耀商品；模型目前每个陪玩只绑定一个游戏。
- 原 `test-customer` → `test-user-01`；原 `dev-player` → `test-partner-01`；原 `test-partner` → `test-partner-02`。只统一用户名及昵称，保留账号 ID、头像、订单、聊天和陪玩档案。
- 旧超级管理员保留用于维护，不计入这 7 个测试账号，不用于模拟普通客服。两位测试客服是普通 staff，不是 superuser；当前员工后台权限仍较宽，并非独立细分的客服权限系统。
- 不通过删除旧订单或重绑真实微信的方式整理测试账号。历史记录中的昵称可能展示统一后的新名称。

## 登录方法

- 用户／陪玩：访问 `http://127.0.0.1:5173/#/pages/login/index`，选择中文账号名称登录。切换账号前从“我的”退出，再重新选择。
- 客服：访问 `http://127.0.0.1:5174/`，选择测试客服01/02，输入对应密码。密码保存在本机 `backend/.local-test-accounts.txt`，已加入 Git 忽略规则；不将密码粘贴到仓库文档。
- 微信小程序仍走真实微信登录，不提供冒用微信身份的测试切换入口。多账号模拟联调在 H5 完成；真机微信身份验收另行安排。
- 同时验证多个角色时使用独立浏览器配置文件或不同浏览器；同浏览器多个标签页共享登录数据，不能当作独立身份。

## 初始化与限制

本机已执行初始化，不需要反复执行。其他开发数据库可在 `backend` 目录运行：

```text
python manage.py setup_test_accounts --game-id <已启用游戏的ID>
```

命令仅在 `DEBUG` 与 `ALLOW_DEV_LOGIN` 都开启时运行，一次事务创建/统一 7 个账号。首次创建客服时输出随机密码，请安全保存；重复执行保留 ID、密码、业务记录和接单开关，不重置订单或改绑游戏。遇到真实微信绑定、超级管理员、同名冲突、身份角色冲突时拒绝并回滚。

开发免密登录仅接受固定清单中、已加入测试账号组、启用且没有微信绑定的 5 个普通账号；拒绝任意用户名及客服账号，不自动创建 `dev-player`。生产环境关闭开发登录后不提供测试入口；上线部署应使用独立生产数据，不迁入测试账号和凭据。
