# P3 真实微信登录 — 实施与验收文档

> 进度：2026-09-29。后端与小程序代码已完成并通过测试，真实联调待微信开发者工具填入 AppID 后手动执行（见文末 M3）。

## 一、目标

用微信小程序 `uni.login` 取 code → 后端 `jscode2session` 换 openid → 建立/归并账号 → 签发自有 Bearer Token。取代此前的统一 `dev-player` 演示账号。

## 三、安全措施（数据安全）

1. **AppSecret 只存 `backend/.env`**，根 `.gitignore` 的 `.env` 规则已覆盖，不会提交；`.env.example` 仅放空占位。
2. **AppSecret 永不下发前端**，`jscode2session` 仅在服务端调用。
3. **日志/响应不泄露敏感信息**：wechat.py 仅记录 `errcode`，不记录原始响应（避免 openid/session_key 落日志）；报错文案经映射表白名单化。
4. **openid 不落账号名**：用户名用 `wx_ + sha256(openid)[:20]`，数据库里不以明文 openid 作为 username。
5. **一次性 code**：微信保证 code 5 分钟有效且换过后失效，服务端不缓存 session_key。
6. **账号归并**：`(appid, openid)` 唯一约束 + 事务内 `select` 已有身份，保证同微信用户多次登录映射到同一账号，不产生重复账号。

4. 验证：登录后「我的」页显示新账号昵称（默认「微信玩家」）；再次登录（重进）仍是同一账号（收藏/订单不丢）。
5. 真机预览：若开发者工具正常，再扫码真机验证一次。

### 可能遇到的问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 返回「登录凭证无效或已过期」 | code 已用/过期（重复触发 uni.login 拿旧 code） | 每次登录前重新 `uni.login`，不要复用旧 code |
| 返回「小程序配置无效」 | AppID 与后端 `.env` 不一致，或未在 mp 平台配置服务器域名 | 核对 AppID；正式环境需在微信公众平台把后端域名加入 request 合法域名 |
| 返回「当前账号存在风险」 | 微信对开发账号/新 AppID 的风控 | 换用测试号，或联系微信侧 |
