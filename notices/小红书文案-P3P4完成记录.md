### 正文

**独立开发「游戏陪玩俱乐部」小程序，P3、P4 两个阶段终于收官了！** 🎉

很多人问独立开发者做这类平台，最难的是什么？不是写页面，是**把一整套业务闭环想清楚、再稳稳落地**。这两阶段我踩的坑，值得记录一下：

---

**P3 · 真实微信登录 🔐**

▫️ 之前一直用统一演示账号，这阶段换成了真·微信登录
▫️ 链路：`uni.login` 取 code → 后端 `jscode2session` 换 openid → 建号/归并 → 签发自有 Token
▫️ 重点做的是**数据安全**：
  - AppSecret 只存 `.env`，永不进版本库、永不下发前端
  - openid 不落账号名（`wx_ + sha256(openid)`）
  - 同 openid 重复登录自动归并，不重复建号
  - 报错文案白名单化，日志不泄露敏感信息

▫️ 结果：微信开发者工具真机联调通过，21 项测试全绿 ✅

---

**P4 · 订单与派单服务 📦**

这阶段才是真正的硬骨头——**完整的履约状态机**：

▫️ 8 态订单流转：待付款 → 待派单 → 待陪玩确认 → 已接单 → 服务中 → 待验收 → 已完成（+ 已取消）
▫️ 下单选「预约日期 + 三档时段（上午/下午/晚上）」
▫️ 陪玩入驻：用户申请 → 管理员审核 → 建陪玩档案（绑游戏分区 + 接单开关）
▫️ 人工派单 + 陪玩接单/拒单，**时段冲突自动拦截**（同一陪玩同时段重复派单会被 409 挡下）
▫️ 管理端全套：订单增删改查、陪玩审核/档案管理/派单

▫️ 结果：后端 43 项测试通过、双端类型检查 + 构建全绿 ✅

---

**这阶段我修的几个隐蔽 bug（独立开发者真实写照）：**

🐛 `PATCH /me/` 更新资料后，陪玩工作台入口凭空消失
→ 根因是 PATCH 响应漏返回 `is_partner` 字段，前端整表覆盖导致状态丢失

🐛 管理端「接单开关」点了没反应
→ `select_for_update` 没包事务，SQLite 本地测试掩盖了，真实 PostgreSQL 直接 500

🐛 管理端审核接口 500
→ 同样是「select_for_update 缺事务」这一族的坑

> 心得：**本地 SQLite 跑得通 ≠ 生产 PostgreSQL 跑得通**，乐观锁 + 行锁这类并发代码，一定要在真实数据库上过一遍。

---

**技术栈速览** 🛠️
- 后端：Django 5 + DRF + PostgreSQL（Docker）
- 小程序：uni-app（Vue3 + TS）
- 管理端：Vue3 + Element Plus
- 亮点：乐观锁版本控制、幂等建单、CSRF+Session 管理端鉴权、Bearer Token 小程序鉴权
