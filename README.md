# 🎮 GamesClub — 游戏陪玩俱乐部系统

一个面向**游戏陪玩俱乐部**的客户服务与内部管理系统：客户用**微信小程序**浏览游戏、下单预约、付款；运营与管理员用 **Web 后台**管理游戏、商品、首页配置和订单。两端共用同一套 **Python 后端** 和 **PostgreSQL** 主数据库，账号、订单、商品不维护双份真值。

> 当前进度（2026-10-16）：已接入真实微信登录、订单与派单、模拟售后结算、订单私信与站内客服；客服确认接单人、陪玩开始及申请完成、客户同意后完成。新增频道公开图文动态、点赞评论、游戏陪玩榜单，以及提交订单页内的选择陪陪底部弹窗。仍属本地开发验证阶段，支付/退款未接真实资金，未部署生产。本次频道与弹窗尚未微信真机验收。
>
> 发布需要做什么、哪些代码可复用，见 [正式发布准备与差距评估](./notices/正式发布准备与差距评估.md)。当前功能详见 [PROJECT_OVERVIEW.md](./PROJECT_OVERVIEW.md)，历史完成记录不等于正式发布验收。

### 2. 管理后台 Web（Vue 3 + Element Plus）

独立管理端，覆盖运营日常操作，关键订单和目录写操作带审计与版本冲突保护：

- **登录 / 概览**：Session + CSRF 认证，数据看板
- **游戏 / 类型 / 商品**：增删改查、图片上传（服务端重新编码）、上下架、停用、**一键投放首页**（新增/编辑商品时直接勾选轮播/特价/人气，自动同步首页配置，无需重复新增）
- **首页配置**：轮播 / 特价 / 人气条目编排
- **订单**：查询/人工建单，未付款订单编辑/删除；客服确认接单；陪玩在会话开始及申请完成，客户最终验收（版本/权限/游戏归属/预约冲突检查）
- **陪玩**：入驻申请审核（通过 / 驳回）、陪玩档案管理（绑分区 + 接单开关 + 编辑 / 删除，有未完成订单时删除受保护）
- **售后复核**：售后案件列表与复核（通过建预留退款 / 驳回）、展示申请原因与复核说明、模拟退款执行（成功 / 失败 / 未知）；已付款未开始取消退款已有后端接口，尚无专用页面
- **结算**：发起结算批次（订单过售后时限且无处理中售后 / 退款才可结算，锁单 + 整数分抽成 + 陪玩收益分成）
- **客服会话**：用户、陪玩与客服双向文字沟通，共享收件箱、未读／待回复筛选；业务列表显示期间每 5 秒自动更新
- **客服配置**：站内客服可直接使用；微信原生／企业微信为额外渠道，仅超级管理员可配置
- **抽成与售后配置**：统一抽成比例（基点）、售后时限（小时）全局配置（仅超级管理员）
- **审计日志**：关键写操作全程留痕（不记录密码与 Token）

![管理端订单列表](notices/e2e-screenshots/03-admin-orders.png)

### 3. 统一后端（Django 5 + DRF + PostgreSQL）

- 多游戏分区、服务商品、账号与角色权限模型
- 订单：服务端订单号、金额快照、**8 态状态机**、幂等键（`Idempotency-Key`）并发保护
- 陪玩：入驻申请、档案、客服确认实际接单人、订单会话内开始 / 申请完成、客户确认履约
- **评价**：订单完成后一单一评（`Review` 模型 OneToOne 订单）
- **售后**：售后案件（`AfterSaleCase`）、图片凭证上传接口（鉴权私有下载与端内上传界面待完善）、退款（`Refund`）、管理员复核；售后窗口可配置
- **结算**：结算批次（`Settlement`）+ 明细（`SettlementItem`），`select_for_update` 锁单、整数分抽成（`commission_bp`）、陪玩收益分成；历史订单回填 20% 抽成
- 收藏、模拟付款、退出撤销 Token
- 公开社区图文、点赞、评论持久化，作者删除与管理员隐藏；按游戏的完成订单数生成榜单
- 版本冲突检测（409）、修改前后日志、`X-Request-ID` 请求追踪
- **真实微信登录**：`WechatIdentity` 模型 `(appid, openid)` 唯一归并，AppSecret 仅存服务端 `.env`

## 🏗️ 技术架构

```
┌─────────────────────┐        ┌─────────────────────┐
│  客户微信小程序       │        │  运营/管理 Web 后台    │
│  uni-app · Vue3 · TS │        │  Vue3 · Element Plus │
└──────────┬──────────┘        └──────────┬──────────┘
           │  Bearer Token                │  Session + CSRF
           └──────────────┬───────────────┘
                          ▼
              ┌───────────────────────┐
              │   Python 后端 (Django 5 + DRF)  │
              │  core 单 app · 统一业务逻辑      │
              │  · 商品 / 订单 / 收藏 / 登录      │
              │  · 版本冲突 / 幂等 / 审计 / 微信   │
              └───────────┬───────────┘
                          ▼
              ┌───────────────────────┐
              │   PostgreSQL 17 (Docker)  │
              └───────────────────────┘
```

- **小程序**与**后台**共用同一业务后端与数据库，金额、状态、版本同源
- 管理端走 `Session + CSRF`，小程序走 `Bearer Token`，微信登录走 `code2session`

## 🚀 快速开始

> 详细步骤与验收边界见 [《第三阶段完成度与联调手册》](./第三阶段完成度与联调手册.md)。

### 后端

```powershell
cd backend
python -m pip install -r requirements.txt
docker compose up -d db                 # 启动 PostgreSQL 17
copy .env.example .env                  # 配置 DATABASE_URL / 微信 AppID 等
python manage.py migrate
python manage.py seed_demo              # 首次空库补示例数据
python manage.py createsuperuser        # 创建后台管理员
python manage.py runserver 127.0.0.1:8000
```

### 管理后台

```powershell
cd apps/admin
pnpm install
pnpm dev                                 # http://127.0.0.1:5174
```

### 小程序

```powershell
cd apps/miniapp
pnpm install
pnpm build:mp-weixin                     # 产物 dist/build/mp-weixin
# 微信开发者工具导入 dist/build/mp-weixin，填入 AppID
```

## 🔒 安全说明

- 微信 `AppSecret` 仅存于 `backend/.env`（已被 `.gitignore` 忽略），**不进入版本库、不下发前端、不落日志**
- 用户 openid 不落账号名（用 `SHA-256` 哈希派生用户名）
- 关键管理操作写入审计；客服消息保存发送员工，不记录密码与 Token
